How much does a Claude Code session cost?

Measured across 66 real sessions: the median is $4.08, the 90th percentile is $11.42 — but one extreme session hit $1,278. Here's the distribution and what drives the spread.

The measured distribution (n=66)

These numbers come from 66 real Claude Code sessions, measured locally with tokenscope. All sessions belong to one heavy user (the tool's own development), so it's a reference set — not a census. Labelled clearly.

Total across all 66 sessions: $2,650.90 over 4,339 turns. The distribution is right-skewed — most sessions are in the $2–$9 range, but a small number of very long sessions pull the average up significantly.

Extreme outlier (n=1 detailed study): one session ran 1,270 turns, peaked at ~998,000 tokens of context, and cost approximately $1,278. Read the full breakdown at the anatomy study.

What drives the cost spread?

A Claude Code session isn't priced like a chat. On every turn, the client re-sends the entire accumulated context to the model. As a session grows — reading files, running commands, accumulating history — that context grows, and so does the per-turn cost.

Pooled across all 66 sessions, the spend breaks down as:

BucketShare of total spendWhat it is
Cache read60%Context re-sent every turn (the dominant line)
Cache write25%New context written into cache (files opened, tool results)
Output15%Tokens the model actually generated
Fresh input~0%Uncached prompt tokens

The key insight: the model writing code is only 15% of a typical bill. The majority is re-sent context — paying to re-read the same files and history on every turn.

Why does session length matter so much? The cost grows roughly as context_size × number_of_turns × cache_read_rate. Double the context and run twice as many turns, and the cache-read cost is roughly 4× higher — not 2×.

Caching helps — but doesn't make it free

Prompt caching is why long sessions don't cost 10× what a short chat does. The Anthropic documented rates (verify for your tier):

  • Cache read = 0.1× the input rate. Re-sending 100k tokens of context costs a tenth of what sending 100k fresh tokens would cost.
  • Cache write = 1.25× (5-minute lifetime) or 2× (1-hour lifetime) of the input rate — a one-time cost when context is first written.

The catch: 0.1× of a 400k-token context, paid on every turn of a 200-turn session, still adds up to a meaningful number. Caching lowers the multiplier; it doesn't eliminate the fundamental cost of long sessions.

FAQ

How much does the median Claude Code session cost?

$4.08, based on 66 real sessions. Most sessions fall between $1.63 and $11.42 (p10–p90). This is a single-user reference set, not a representative survey.

Why did my session cost $100+?

Outliers happen. An extreme 1,270-turn session cost $1,278 in the measured data. Long sessions where the model carries hundreds of thousands of tokens re-send that context every turn. A session with 500k context running for 200 turns incurs roughly 500k × 200 × (cache_read_price) in read cost alone. See the anatomy study for the full breakdown.

What's the fastest way to reduce session cost?

Start a fresh session or use /compact before the context grows very large. Context keeps growing by default — compacting or restarting resets the per-turn re-send cost. The cost reduction guide has a concrete checklist.

Is the $4.08 median for Sonnet or another model?

The sessions in the n=66 dataset were measured with tokenscope's default pricing applied to the token counts in the session logs. The model used in each session affects output pricing and cache rates — tokenscope applies the documented pricing for the model recorded in each turn. The benchmark page documents the exact method.
