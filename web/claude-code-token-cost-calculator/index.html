The cost formula explained

A Claude Code session's cost has three components. The dominant one depends on session length:

Cache read cost (dominant in long sessions):
≈ average_context_tokens × turns × (input_rate × 0.1)
Context grows through the session, so the average is lower than peak. For a rough upper bound, use peak context × turns × 0.1 × input_rate.
Cache write cost (one-time per unique context block):
≈ new_context_tokens × (input_rate × 1.25) — 5-minute cache
≈ new_context_tokens × (input_rate × 2.0) — 1-hour extended cache
This is paid once when context enters the cache, not on every re-read.
Output cost:
≈ output_tokens_per_turn × turns × output_rate
Measured at ~15% of pooled spend across 66 real sessions — smaller than most people expect.

What the estimator can't tell you

The estimator above is a simplified upper-bound model. It assumes peak context for all turns, which overestimates early-turn cost. The real pattern:

  • Early turns: context is small, cost is low.
  • Late turns: context is large, each turn is expensive.
  • The total grows roughly quadratically with session length (if context grows linearly with turns).

The only way to see the actual breakdown for your sessions — per turn, per model, with real cache-read vs cache-write vs output attribution — is to measure it directly.

FAQ

Why is 1,000 tokens so cheap but a session costs $10+?

Because a session re-sends large amounts of context on every turn. A typical 44,900-token context, re-sent 29 times (the median), at the cache-read rate of 0.1× input price, accounts for most of the bill — not any single 1,000-token message. The per-token rate is low; the total token volume across a session is high.

How accurate is the quick estimator?

It's a rough upper bound for the cache-read component (assumes peak context for all turns). Real sessions grow gradually, so actual cost is lower. Use it for order-of-magnitude estimates. For exact numbers, run tokenscope on your actual session logs.

Where do I find current Claude model pricing?

At anthropic.com/pricing. Prices change — always verify before making decisions. tokenscope uses the documented rates at measurement time and shows which rates were applied in the output.
