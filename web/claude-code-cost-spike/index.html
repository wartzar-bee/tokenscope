Why did my Claude Code cost spike?

Almost always: a single session that ran a very long time with a large context. In the n=66 benchmark data, one session cost $1,278 while the median was $4.08. Here's how to find it, understand it, and prevent the next one.

The anatomy of a cost spike

Claude Code sessions are priced on every turn re-sending the full accumulated context. This creates a super-linear cost pattern: a session that runs much longer than usual doesn't just cost proportionally more — it costs disproportionately more.

The typical pattern:

  1. Session starts normally. A few files read, a few commands run. Context is 20–50k tokens. Turns cost fractions of a cent each in cache-read cost.
  2. Task expands. More files pulled in. Large command output accumulated. Context grows to 200k, 400k, 800k tokens. Each turn now re-sends all of that at 0.1× input price.
  3. Session keeps running. 100, 200, 500+ turns. The per-turn cost is now much higher than it was in the first 30 turns. The session is still running, and the bill is compounding silently in the background.
The $1,278 session: 1,270 turns, ~998k peak context, 66% of cost from cache-read alone — paying to re-send nearly 1 million tokens of context, every turn. Full breakdown at the anatomy study.

How to diagnose a spike

The fastest way to find the culprit session:

Run tokenscope to see all sessions ranked by cost:

npx @wartzar-bee/tokenscope

Local, read-only. Reads ~/.claude/projects/**/*.jsonl. No upload. MIT.

tokenscope shows:

  • All sessions sorted by cost
  • Per-session turn count, peak context, and spend split (cache-read / cache-write / output)
  • The context growth curve — when in the session context ballooned

The spike session will be at the top of the cost list. The context growth curve shows you exactly where in the session the context grew to expensive territory.

Common spike triggers

TriggerWhat happenedHow to avoid
Reading a large file or repo One large file (or many medium ones) pushed context from 50k to 300k+ tokens in a few turns Only load files the model needs for the current subtask; close files when done
Verbose command output A command with very long output (logs, test results, build output) added tens of thousands of tokens to the context Redirect verbose output to files; paste only relevant excerpts
Session scope creep Started with one task, kept adding new tasks without starting a fresh session — context carried all prior task history Start a new session for each distinct task or codebase area
No /compact on a long session Session ran 100+ turns without compacting — by turn 100, the early file reads and tool results were still in context even though the model no longer needed them Use /compact at natural breakpoints (when you're shifting to a new subtask)

The prevention checklist

These three habits prevent most spikes:

  1. Compact proactively. Use /compact when you finish a significant subtask or when you notice context has grown large. See when to use /compact.
  2. Fresh sessions for new tasks. Don't carry context from one task into the next. A fresh session starts at low cost; a continued session carries all prior context for the cost of every subsequent turn.
  3. Check your sessions periodically. Running tokenscope after a work session shows you which sessions are trending expensive, before the cost has fully accumulated in a multi-day session.

The full cost reduction guide covers each of these in detail, with additional techniques for keeping context small.

A $10–15 session is within normal range for a longer day of coding. A $50+ session suggests a session ran significantly longer than intended, or a large file read pushed context to expensive territory. A $100+ session almost always has an identifiable cause in the session logs.

FAQ

Can I get a refund for a session that spiked unexpectedly?

tokenscope can't help with billing — contact Anthropic support. tokenscope can help you understand exactly what happened in the session: which file reads grew the context, which turns were most expensive, and what the total breakdown looks like.

Why didn't Claude Code warn me before the context got expensive?

Claude Code shows a context usage indicator, but it doesn't show the real-time cost of that context being re-sent. The cost is invisible until you look at the API bill or run a tool like tokenscope that reconstructs the cost from the session logs.

Is there a way to set a spending limit for a single session?

Not natively in Claude Code. The practical equivalent is setting a personal rule (e.g. compact or restart when the context indicator shows 100k+ tokens) and running tokenscope regularly to monitor actual spend patterns.
