Claude Code: Sonnet vs Haiku cost

Haiku is cheaper per token — but in a long agentic session, the model's output rate applies to only ~15% of spend. The other 60% is re-sent context (cache-read), which scales with each model's input rate.

How spend is actually distributed in a Claude Code session

Before comparing models, it's worth knowing where the money goes. From 66 real sessions measured with tokenscope, pooled spend splits as:

BucketPooled shareWhich rate applies
Cache read60%0.1× the model's input rate — re-sent context
Cache write25%1.25–2× the model's input rate — first-time context
Output15%Model's output rate — what the model generated
Fresh input~0%Model's input rate — uncached prompts

Model choice affects all these rates — but proportionally, output is only 15% of spend in a typical long session. The other 85% scales with input/cache rates, which differ between models but by a smaller ratio than output rates.

Important: Anthropic updates model prices. Always verify current rates at anthropic.com/pricing before making cost decisions. tokenscope uses the documented rates at measurement time.

What the model choice actually changes

Claude Haiku models are priced lower than Sonnet models per token. The cost impact in a session depends on the spend distribution:

  • If output is 15% of spend: switching to a model with half the output rate saves ~7.5% of total session cost. Meaningful but not transformative.
  • If output is 40%+ of spend (short, high-output sessions): model choice is a much larger lever — potentially 20%+ total savings from a cheaper output model.
  • If the session is extremely long (cache-read >80% of spend): model choice matters primarily through the input/cache rate difference, which is typically smaller in ratio than the output rate difference.

The headline: for a session that looks like the measured benchmark median (29 turns, $4.08, ~60% pooled cache-read), switching models changes the bill by a fraction of what reducing context or session length would save.

The bigger levers

Measured data from 66 sessions shows that session length and peak context size are more powerful cost levers than model choice for typical agentic usage:

  • The difference between the p10 session ($1.63) and p90 session ($11.42) is 7×. That's mostly driven by session length and context, not by model selection across those sessions.
  • The extreme session ($1,278) reached ~998k peak context. The same task done with active context management — compacting at 100k, restarting for new subtasks — would cost a small fraction of that, regardless of which model was chosen.

Model choice is still a real factor — especially for budget-constrained users. But the biggest savings per unit of effort come from managing session length and context size first.

When Haiku is the clear choice for Claude Code

Haiku tends to make more sense when:

  • The task is well-defined and bounded. Simple code generation, formatting, straightforward refactors — tasks where output volume is predictable and the capability gap between Haiku and Sonnet doesn't affect quality.
  • You're running many short sessions. Short sessions have a higher output fraction relative to cache-read, so the model's output rate matters more.
  • Budget is the primary constraint and some quality trade-off is acceptable.

Sonnet tends to make more sense when the task is complex, multi-step, or requires reasoning that a cheaper model handles less reliably — because a failed attempt that requires a longer follow-up session can cost more than using the better model from the start.

FAQ

Is Haiku significantly cheaper than Sonnet for Claude Code?

Haiku has lower per-token rates, but in a typical long agentic session where cache-read is ~60% of spend, the total savings depend on the ratio of input/cache rates between models — not just output rates. The savings are real but often smaller than expected for long-session usage. Short, high-output sessions see a bigger benefit.

Does tokenscope track which model was used in each session?

Yes. The session logs record the model for each API call. tokenscope reads those records and applies the appropriate pricing for each turn. If you've used multiple models across different sessions, the breakdown is visible per session.

What if I'm on a Claude Max subscription?

Subscription pricing decouples cost from token counts for most usage. tokenscope measures token usage and estimates cost using Anthropic's documented API rates — it's most useful for understanding the volume and distribution of token usage, which drives API costs and subscription tier selection.
